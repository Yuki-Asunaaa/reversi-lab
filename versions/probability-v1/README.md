# Reversi Lab · 黑白棋实验室

人工智能课程实践项目：Python 标准库实现棋规与搜索，本地网页提供立体棋子、翻转动画和实验界面。无需安装第三方运行依赖，不连接云端 AI，不使用现成的黑白棋或搜索算法库。

## 运行

需要 **Python 3.9 或以上**和现代 Edge、Chrome、Safari 或 Firefox。

```bash
cd reversi-lab
python3 main.py
```

程序自动打开 <http://127.0.0.1:8765>。保留终端窗口，按 `Ctrl+C` 结束服务。

- macOS：也可双击 `启动黑白棋.command`。
- Windows：安装 Python 后双击 `start_windows.bat`，或运行 `py -3 main.py`。
- 指定其它端口：`python3 main.py --port 8766`。
- 不自动开浏览器：`python3 main.py --no-browser`。
- 网页必须通过本地服务打开，不能直接双击 `web/index.html`。

一个服务实例共享一盘棋。刷新网页不会重置棋局；重启服务会重置棋局。最近一次已完成或已停止的批量实验会保存并自动恢复。

## 功能与操作

### 对弈空间

1. 选择 **PvE**（人类对 AI）或 **Eve**（AI 对 AI）。PvE 可以选择人类执黑或执白。
2. 每个 AI 方独立选择 Minimax、Alpha-Beta、MCTS 或 V1／V2／V3 三代创新策略，旧版仍可选择。
3. 思考时间档位：**0.05、0.2、0.5、1、3、10、30 秒**，支持 0.05～59.5 秒自定义上限。默认 3 秒。
4. 点击开始。人类通过点击合法落点下棋；可关闭合法落点提示和动画。
5. 运行中修改算法、时间或控制模式，从**下一回合**生效，当前已开始的回合保持原设置。要立刻更换双方身份，可新建对局。
6. 人类回合可立即暂停，累计用时不会丢失。AI 回合会在当前落子完成后暂停。继续时恢复对局。
7. 行棋记录保存每步算法、时间上限、实际耗时、搜索耗时、节点数、深度与 MCTS 模拟数。可导出 JSON。

**计时口径：**每回合先由统一分析器分析局面，然后开始该方的落子计时。主计时包含搜索进程启动和协调开销；“搜索观察”显示算法本身耗时。因此 0.2 秒搜索档位的实际回合用时可能略大于 0.2 秒。人类和 AI 在运行中的单步超过 60 秒均判负。统一分析与暂停不计入落子时间。设置最大 59.5 秒，为启动和返回留出余量。

### 算法实验

- 选择至少两种算法、一个或多个时间档位，以及每组算法的换色对局组数。
- 每组算法用相同的合法随机开局，交换黑白进行两局；同一组开局也用于不同时间档位。
- 一次只运行一个搜索任务，不运行界面胜率分析，避免额外分析抢占计算资源。
- 实时显示已完成局数、胜／和／负、胜率、得分率和平均搜索时间。
- 停止实验会保留已经完整结束的棋局；中止的棋局不会进入统计。
- 导出 CSV 汇总和 JSON 完整棋谱。文件自动保存到 `results/latest_experiment.json`。
- 得分率 =（胜局＋0.5×和局）/ 总局。胜率 = 胜局 / 总局，两者不能混称。

也可以从命令行运行：

```bash
python3 tools/benchmark.py --seconds 0.2 0.5 --pairs 3
python3 tools/benchmark.py --algorithms alphabeta hybrid --seconds 1 --pairs 5 --output results/ab_vs_hybrid.json
```

界面默认勾选三种基线与 V3；命令行未指定算法时比较全部六个版本。`--pairs 1` 代表每对算法共 2 局；四种算法、一个时间档位共 12 局。少量棋局只能作为演示与初步观察，不能据此保证某算法普遍更强。时间限制搜索受操作系统调度影响，固定种子能复现开局与随机流，但不保证不同机器得到逐步完全一致的棋谱。

## 自行实现的算法

| 模型 | 核心实现 | 实验解释 |
| --- | --- | --- |
| Minimax | Negamax 写法的完整极小极大搜索，迭代加深 | 在上一完整层完成后保留可用结果；不做 Alpha-Beta 剪枝 |
| Alpha-Beta | 在相同评估、走法排序与迭代加深基础上加入 α/β 剪枝 | 同一固定深度的最佳评分应与 Minimax 一致，通常访问更少节点 |
| MCTS | UCT 选择、扩展、终局模拟、回传；以根子节点访问次数选着 | 模拟策略优先角点、避开空角旁危险格，其余随机选择；和棋回报 0.5 |
| V1 阶段混合（`hybrid`） | 空格 >12 使用同一 MCTS，≤12 切换 Alpha-Beta | 原版保留，旧实验始终对应这一版本 |
| V2 缓存主变化搜索（`hybrid_v2`） | PVS、置换表、迭代加深、历史与杀手着排序；保留基线评估 | 同深度最佳分数与基线一致，争取同时间搜索更深 |
| V3 动态评估混合（`hybrid_v3`） | V2＋愿望窗口＋动态角邻格、潜在行动力与阶段性评估 | 冻结参数后通过新开局换色验证短时优势 |

共同优化：两个整数构成位棋盘；批量生成合法着法；纯状态对象便于分支搜索；统一的单调时钟与取消信号；AI 进程与页面服务分离。

确定性算法使用相同阶段性评估，包括位置权重、行动力、角点、保守稳定边线子、前沿棋子和随阶段变化的子数权重。“稳定子”只计算从已占角点连续延伸的同色边线，避免把未证实稳定的棋子当作稳定子。搜索深度按实际落子数计算，PASS 不消耗深度。

搜索统计口径：确定性算法记录搜索树访问状态，MCTS 的状态数包含树中选择／扩展和模拟中的状态；这两类状态数不能直接视作同等搜索深度或同等棋力。根节点非最佳候选的 Alpha-Beta 评分可能是界限，界面只展示最佳推荐，不把这些界限换算成候选胜率。

## 实时估算胜率

主界面始终采用**统一三层 Alpha-Beta 分析器**，不随对弈双方的算法切换评分尺度。把黑方视角评分和棋局阶段作为特征，通过项目自对弈结果拟合三分类 Softmax 模型，给出黑胜／和棋／白胜概率。

- 随机合法开局长度为 4、6、8、10 或 12 步；之后双方使用三层 Alpha-Beta。
- 附带 128 盘校准对局：96 盘训练，32 盘保留验证。按整盘划分，避免相邻局面跨训练／验证集合。
- 训练样本包含黑白镜像；模型显式约束颜色对称。梯度与 Adam 优化器由 Python 自行实现。
- “项目说明”展示保留验证的多分类 Brier、对数损失、类别先验基线和概率分组观测比例。指标越小越好，不能解读成百分比准确率。
- 这些概率只描述参考自对弈水平，不代表任意人类或任意搜索强度的真实胜率。数据量有限，同局面轨迹中的样本也不是相互独立的。
- 如果三层分析尚未完成或模型文件缺失，则显示“待充分分析”，不编造百分比。
- 当剩余 ≤10 个空格时尝试完整搜索；若成功，改为展示“双方最佳应对下”的胜／和／负结论，明确区别于概率。
- 终局显示实际结果；超时终局也以超时判定为准。

重建校准数据：

```bash
python3 tools/calibrate.py --games 128 --seed 20261014
# 复用已有对局，重新拟合参数：
python3 tools/calibrate.py --reuse
```

对弈和批量实验会占用计算资源，正式测量时不要同时运行校准脚本或其它重负载程序。

## 检查

```bash
python3 -m unittest discover -s tests -v
```

核心检查包括：独立矩阵规则与位棋盘对照 50 盘随机完整棋局；八方向同时翻子；非法落子；强制 PASS；未满盘终局；同深度 Minimax/Alpha-Beta 评分一致；小残局精确搜索；时间预算与取消；概率归一化与颜色对称；暂停和 60 秒超时判负。

## 作业对应

- 8×8 棋规和图形人机交互：`board.py` 与对弈空间。
- 每步及累计时间、超时失败：`session.py`、计时区和行棋记录。
- 三种算法（包括 MCTS）：`search.py`，以及可选的独立对照实验。
- 自主尝试：分阶段混合策略、统一且可校准的胜率分析、可追溯的换色实验。
- 交付范围为项目与运行说明；实验报告和腾讯会议画中人汇报视频不包含在本次项目中。

算法概念参考：课程要求中的 Minimax／Alpha-Beta／MCTS；概率校准的方法思路参考 [Stockfish 官方 WDL 模型说明](https://github.com/official-stockfish/WDL_model)。本项目未复制或调用 Stockfish，也没有加载外部棋类引擎或预训练参数。
